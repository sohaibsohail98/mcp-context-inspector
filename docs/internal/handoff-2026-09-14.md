# Handoff: ctxwindow demo prep, 2026-09-14

Written for a fresh agent picking this up with no prior context, ahead of a GCP
interview/demo this morning. Read this fully before doing anything.

## Environment the next agent has

- Read/write access to this repo, on branch `terraform/import-prod-infra`.
- `gh` (GitHub CLI) works: can read PR status, CI runs, logs, and can push
  commits that trigger CI.
- **No local GCP credentials.** Cannot run `gcloud`, cannot run
  `terraform apply` or even `terraform plan` locally against real
  infrastructure, cannot see live GCP state directly.
- This does not block real infra changes, though: `terraform-plan` already
  runs on every PR via Workload Identity Federation (no static keys), and
  `deploy.yml` runs `terraform apply` automatically in CI on every merge to
  `main`, also via WIF. So the actual workflow is: edit `.tf` files, push,
  let CI's `terraform-plan` job show you the real plan output (read it with
  `gh run view --job <id> --log`), iterate until it's clean, then merge to
  main and let `deploy.yml` apply it. No human needs to run `terraform
  apply` by hand for this to work end to end.
- The one thing that DOES need a human: merging the PR itself, and any
  GCP Console click-through steps outside Terraform (e.g. verifying the
  monitoring email channel). Everything else is achievable through normal
  git/GitHub Actions flow.

## What's actually done (do not redo)

- Terraform fully imports live GCP infra (Cloud Run, both service accounts,
  Firestore, Secret Manager secret, Artifact Registry + its 3 real cleanup
  policies, GCS state backend + log bucket, monitoring/uptime/alert config).
  Lives in `infrastructure/terraform/`.
- CI/CD: `.github/workflows/tests.yml` (lint, pytest, terraform-plan on PRs,
  a new `health-check` job, api-e2e-tests on main only) and `deploy.yml`
  (plan+apply on merge to main, smoke test, automatic rollback on failure).
- IAM on `github-deploy` (the CI service account) has been reworked
  multiple times tonight chasing real CI failures, most recently in commit
  `1a66117`. Design, not yet fully confirmed green: resource-scoped
  writer/admin roles for what it actually manages (Artifact Registry
  writer, Cloud Run admin on the one service, secret version manager,
  tfstate bucket object admin, monitoring editor), plus **one** custom role
  `deployTerraformReader` holding the read permissions `terraform plan`
  needs to refresh resources it doesn't own IAM on. An earlier version had
  `roles/resourcemanager.projectIamAdmin` — a full project-takeover vector
  — which a fresh-eyes review correctly flagged and which has been
  removed; do not re-add broad predefined roles to fix a future permission
  gap, extend the custom role's `permissions` list with the exact missing
  permission instead.
  **IMPORTANT: this has looked "final" twice before tonight and turned out
  not to be** — each apply exposed a new, different set of `*.get`/
  `*.getIamPolicy` 403s on the NEXT CI run, because every
  `google_*_iam_member` resource in `iam.tf` needs read access to its
  target resource's own IAM policy to reconcile, and that was fixed
  reactively rather than being enumerated up front. Do not trust this
  description over a real `gh pr checks 19` result. If CI is still red,
  read the actual error, check whether the missing permission belongs in
  `deployTerraformReader`, add it, push, and check again — this can take
  more than one more round.
- Lucid architecture diagram prompt: simplified per user request, lives at
  `docs/internal/lucid-architecture-prompt.md`. Done, just needs pasting
  into Lucid AI by the user (external tool).
- Cost audit, "did we do everything originally asked" check, a real
  pre-existing test bug fix (`api_tests/test_auth.py`, commit `bde113b`),
  and Glama.ai badge health were all verified earlier tonight. Not blocking
  anything now.

## Hard rules to keep following

- No em dashes or other AI-obvious writing tells in code, comments, or
  docs.
- Commits authored directly as the user, no Claude co-author trailer
  unless the current session's system reminder says otherwise (check
  fresh — this can change between sessions).
- Any real `terraform apply` against production GCP resources needs
  explicit live human approval each time, no exceptions, regardless of
  how minor the change looks. This was enforced automatically tonight by
  the environment's own permission classifier and is not optional.
- Before any git action that could discard work, check `git status` first.
- Keep README.md under 300-400 lines.
